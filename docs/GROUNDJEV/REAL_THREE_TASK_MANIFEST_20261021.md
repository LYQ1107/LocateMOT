# Real three-task source manifest — 2026-10-21

The old full-source OneJev manifest was not safe for an independent held-out
comparison: its source inventory included MOT20-05 rows. I prepared a new
streamed manifest at
`/data2/user/LocateMOT_GroundJEV/outputs/groundjev/training_data/real_three_task_joint_v1/`
without launching an optimizer.

The manifest contains 131,990 rows: 131,214 native MOT identity rows, 330
native RMOT membership rows, 16 native RMOT empty-query presence rows, and 430
registered OVMOT Base teacher-control rows (215 group + 215 leaf). Each source
was streamed, checked for duplicate IDs, train split, task family, media
paths, forbidden MOT20-05/test markers, row count, and SHA-256. The source
manifest receipt records zero optimizer updates and zero GPU launches.

The native TAO archive is registered separately: 40 frames and 35,228 native
candidate boxes, with receipt status
`COMPLETE_LEGAL_NATIVE_VOCABULARY_AND_ROI_STREAM`. It is a validation/native
replay archive and has no category labels. It therefore cannot be converted
into OVMOT training targets by copying detector labels or by guessing boxes.
Native OVMOT training rows remain pending; the current manifest is a legal
three-task source registration with an explicit teacher-control boundary, not
a completed joint-training result.

The reproducible registration is described by
`configs/groundjev/real_three_task_joint_v1.json` and generated by
`tools/groundjev/prepare_real_three_task_joint_manifest.py`. The old
four-GPU resume queue remains paused and was not restarted against this
manifest. A future optimizer launch must first materialize native TAO
train-split category rows, validate the runtime OneJev environment, and create
a new run directory/checkpoint lineage.
